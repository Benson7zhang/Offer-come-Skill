# 可选筛选项与匹配语义

选项为配置目录，不是对BOSS当前UI的承诺。运行时读取真实菜单；菜单不支持的条件转为JD筛选。每项允许不限、多个值或自定义。

## 可选目录

| 类别 | 可选示例 | 使用说明 |
|---|---|---|
| 岗位方向 | AI应用、RAG、Agent、算法、Java后端、Python、前端、测试、数据、产品、运维 | 方向与职位名称分开，可包含/排除关键词 |
| 职位分类 | 技术→后端开发、大数据/AI；产品→产品经理等 | 读取BOSS当前分类层级，不写死分类ID |
| 招聘类型 | 校招、实习、全职社招、兼职 | 校招再核对毕业年份；实习核对在校身份 |
| 行业分类 | 互联网/IT、人工智能、金融科技、医疗健康、教育、电商、制造、能源、企业服务 | 支持一级/二级分类，按网站当前标签映射 |
| 业务领域 | 金融问答、企业知识库、工业智能、医疗AI等 | JD业务方向，与公司行业不是同一条件 |
| 省份/城市/区域 | 广东、浙江、江苏、四川；深圳、杭州等；区县 | 城市与省份冲突需明确，不静默扩大到省外 |
| 办公方式 | 坐班、远程、混合、不限 | 城市不限不等于接受远程或出差 |
| 候选人学历 | 专科、本科、硕士、博士 | 真实学历；学历筛选为可投门槛，不用来修改资料 |
| 岗位学历要求 | 不限、专科及以上、本科及以上、硕士及以上、博士 | 本科及以上允许本科；硕士必需排除本科候选人 |
| 院校限制 | 排除985、211、双一流、重点院校、一本；或自定义 | 区分“要求”和“优先”，可选择两者都排除 |
| 经验要求 | 不限、在校/应届、1年以内、1–3年、3–5年、5–10年、10年以上 | 实习经历不自动换算全职工作年限；按真实菜单选择 |
| 公司规模 | 0–20人、20–99人、100–499人、500–999人、1000–9999人、10000人以上 | “小公司/大厂”转成区间需说明假设；名气不等于规模 |
| 融资阶段 | 未融资、天使轮、A轮、B轮、C轮、D轮及以上、已上市、不需要融资 | “不需要融资”与“未融资”不同，不推断财务健康度 |
| 公司性质 | 民企、国企、央企、外企、合资等 | 可能需公司页补证，未知不能断言 |
| 公司名单 | 指定公司、排除公司、排除外包/驻场 | 明确“自研”仍可能驻场，正文优先 |
| 待遇 | 日薪范围、月薪范围、薪资月数、餐补/住宿补贴 | 保留单位；不把日薪直接乘30冒充月薪 |
| 到岗/出勤 | 通过面试后几天、每周几天、每天几小时、至少几个月 | 不承诺早于用户可到岗日；7天/大小周等检查正文 |
| 面试与工作条件 | 线上面试、可线下、双休、出差、驻场、转正机会 | 未指定则不擅自代用户接受；必要条件不明暂缓 |
| 招聘活跃度 | 在线、今日/近几日活跃、不限 | 使用可见信息，不能承诺回复概率 |
| 批次与重复 | 每批数量、仅新招聘者、仅联系新岗位 | 跳过已沟通过的招聘者 |
| 开场白 | 简短/适中、是否提学校学历、是否附公开项目 | 不影响真实性和授权边界 |
| 附件 | 求职者自行上传和发送 | 不提供代发功能 |

## 组合规则

- 同一包含列表内部为OR，不同硬条件之间为AND；排除条件优先。比如广东/浙江＋AI应用/Agent＋本科可投，不要求同时在两个省。
- 区分必须满足与排序偏好。未知硬条件暂缓；未知偏好不等于不满足，也不补猜。
- 岗位学历标签和JD冲突，按正文更具体要求；薪资冲突保留两种原文并标待核实。
- 硕士团队成员、与博士合作、硕士优先，与“硕士必需”不同。若用户仅排硬门槛，不扩大为所有出现“硕士”的岗位。院校同理，按用户对院校门槛与优先条件的具体要求执行。
- 薪资筛选默认按岗位区间与意向区间有交集；用户要求“保底”时必须岗位下限达标。补贴另列，不默认并入工资。
- 行业分类与业务领域不能互相代替：医疗公司可以招通用AI开发，互联网公司也可能招非技术运营。
- 用户只选省份时轮换城市；不必穷尽全省才能完成一批，但报告实际覆盖城市。
- 零结果可以推荐放宽选项，不能自行放宽硬条件。不要因数量目标去投明显不匹配岗位。

## 简短配置交互示例

用户只说“用Offer-come投简历”，且没有已知资料时，先问：
“你主要想投什么岗位、哪些城市，以及是只筛选起草还是直接发起沟通？也可以给我简历路径。行业、规模、融资阶段暂按不限。”

已有本机用户资料且说“继续投6个AI岗”，直接沿用已知资料和最新约束；不要再次询问省份、学历或附件权限。

用户说“我想自己选全部条件”，分组提供：岗位与招聘类型 → 地区与工作条件 → 学历与经验 → 行业、规模和融资 → 待遇与发送模式。每组接受自然语言，不强制逐项填写。
