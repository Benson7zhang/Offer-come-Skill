# 发送与核验

1. 先完成JD筛选和定制开场白，确认用户已要求实际投递/沟通。仅筛选或起草时不点击沟通按钮。
2. 读取当前URL、职位、公司、招聘者，确认是目标岗位且显示“立即沟通”。已有联系则跳过。
3. 点击一次并等待对话出现。该按钮可能自动发送账号默认招呼，需向用户说明，不擅自修改默认招呼。
4. 再核对招聘者，填入定制消息并回读完整文字。用户切换页面或聊天时重新定位，不能向新对象发送旧草稿。
5. 发送一次，核实消息完整出现、状态为已发送/送达、输入框为空。点击成功或草稿为空都不能单独证明发送成功。
6. 核验后再处理下一岗位；出现超时或断线先读同一对话状态，不盲目重发。验证码、登录和浏览器授权由用户处理。

简历附件由求职者自行上传、选择和发送；skill不提供附件代发流程。招聘方回复由求职者处理。

## 轻量记录

在当前任务work/offer-come/outreach.jsonl按岗位记录时间、岗位URL、公司、招聘者、发送文字与结果（已核实/失败/未知）。记录默认招呼已发送但定制消息未完成的情况，避免续作再次发起。只保存求职流程需要的信息，不保存Cookie或无关聊天记录。

续作结合记录与页面“继续沟通”状态去重。结果未知不计成功；没有历史文件不代表从未联系。最终数量按岗位计数，不把默认招呼和定制消息分别计数。
